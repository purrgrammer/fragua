## 2. Claim inventory

### 2.1 Lens: STORE (`packages/store`, `packages/types`)

Invariants and write path
1. SPEC §4 I1 / ARCH §0 I1: "Every write is one SQLite transaction; events + projection updated together." Every write opens `BEGIN IMMEDIATE`. Files: `store/src/store.ts` (`writeTxn`), `store-writer.ts`, `pragmas.ts`.
2. ARCH §0 I1 enforcement: the AST lint forbids `await` / `JSON.stringify` / `JSON.parse` / `fetch` / `Value.Check` in `writeTxn`/`db.transaction()` callbacks, in `SAVEPOINT`-wrapped closures (`sweepRun`), and in any helper reachable from them to full transitive depth. It follows imports from `*-queries.ts` and follows `ctx.<m>` / `ctx.store.<m>` / `ctx.blobs.<m>` / `ctx.metrics.<m>`; `ctx.validatePayload` is flagged outright. Files: `store/test/lint.test.ts`, `store-writer.ts`, `store-bundle-import.ts`, `sweep.ts`. AGENTS ground rule 10 repeats this.
3. ARCH §4.1: `gcBlobs`'s "orphan-file unlinks run inside its transactions". Compare with claim 2 (no I/O in txns) and ARCH §0 "Both GC passes unlink files under the same write lock". Files: `store/src/blob-*`, `store-writer.ts`.
4. SPEC §4 I2: "No handler state outside the projection." Files: `core/src/handler/types.ts`.
5. SPEC §4 I3 / ARCH §0: intents always appendable, facts OCC-checked. Two distinct methods, `appendIntent` and `appendFact`. Files: `store-writer.ts`, `event-queries.ts`, `types.ts`.
6. SPEC §3.3: `fact.checkout_released` is the single fact written by the CLI; `IEventWriter.appendIntentWithFact` commits intent plus fact in one OCC transaction and advances `last_applied_seq`. Files: `store-writer.ts`, `core/src/intent-plane`, `cli/src/commands/operator.ts`.
7. SPEC §4 I5 / ARCH §1.1: the idempotency key is `sha256(runId + nodeId + iteration + argsHash + attempt)`. Intent facts are committed in their own txn before `fn`. The startup sweep quarantines orphan `fact.side_effect_intent` rows by joining on `idempotencyKey`. Files: `store/src/sweep.ts`, `event-queries.ts`, `daemon/src/recorder.ts`, `core/src/handler/external-call.ts`.

Size caps
8. SPEC §4 I6 / ARCH §0 I6: `run_state.routing` is under 8 KB by `CHECK (length(routing) < 8192)` and a store pre-check. It is a tripwire. Files: `schema.sql`, `store-writer.ts`.
9. SPEC §4 I7 / ARCH §0 I7: event payloads are under 4 KB. The binding guard is `validatePayload` using `utf8ByteLength`; the `CHECK (length(payload) < 4096)` is a coarse code-point backstop. ARCH §9 describes the pre-check as `s.length >= N`, which differs. Files: `store.ts` (`validatePayload`), `schema.sql`, `store/test/store.unit.test.ts`.
10. ARCH §9: `MAX_BLOB_BYTES` is 16 MiB and inclusive (`> N` rejects). `MAX_MESSAGE_CONTENT_BYTES` is 1 MiB with `MessageTooLargeError`. Four `<` caps put the first rejected size at N. Files: `store.ts`, `schema.sql`, `artifact-queries.ts`, `message-queries.ts`.
11. SPEC §3.3 / ARCH §3 "Observability events": observability events skip OCC and the reducer. An oversize payload is truncated to a routing-preserving marker (`nodeId`, `iteration`), logged, and not rejected. They share the `bumpRunSeq` counter. Files: `store.ts`/`store-writer.ts` (`appendObservabilityEvents`), `store/test/store.unit.test.ts` (log lines at 8048 and 16163 bytes confirm it).

Seq and OCC
12. SPEC §4 I10 / ARCH §1.5: seq is an O(1) per-run counter, `UPDATE run_state SET next_seq = next_seq + 1 RETURNING` inside the append txn, never a `MAX(seq)` scan. P1 asserts `events.seq = 1..NK` contiguous and `next_seq` matching. Files: `event-queries.ts`, `run-state-queries.ts`, `store.property.test.ts`.
13. ARCH §0: `claimNextRun` flips `queued → running` and bumps `version` with no fact (a sanctioned eventless write). A derived `run_state.version` therefore never equals the live one. ARCH §2.1 names `setRunTitle` as the second eventless projection write. Files: `run-state-queries.ts`, `store-writer.ts`, `reducers.ts`, `projection-occ.test.ts`.
14. ARCH §8: the claim order is `priority DESC, ready_at ASC, run_id ASC`. `idx_run_state_queue` covers only the first two columns. `ready_at` resets on every transition into `queued`. P24: K fibers racing `claimNextRun` each claim a distinct run. Files: `run-state-queries.ts`, `schema.sql`, `queries.test.ts`.
15. ARCH §0 / §2.1: `routing` is written only inside an event-append txn, through the reducer fold or `routingPatch` on `appendFact`. There is no out-of-band writer, validation runs on read, and `routingPatch` is validated by `validateRoutingPatch` (a `routing-patch-gate` test exists). Files: `store-writer.ts`, `reducers.ts`, `routing-patch-gate.test.ts`.

Sweep, lock, schema
16. ARCH §1.4 / §6: the startup sweep requeues crash-interrupted `running` rows. It resets `ready_at`, bumps `version`, appends `fact.run_requeued_after_crash`, and preserves `current_node`. It quarantines orphan side effects. It leaves `paused`, `paused_human` and `quarantined` rows alone. Each run is healed in its own `SAVEPOINT`, and a failure records `daemon.sweep_run_failed`. Files: `store/src/sweep.ts`, `sweep.test.ts`, `reducers.ts`. At fold version 6, `fact.run_requeued_after_crash` must preserve `currentNode` (ARCH §1.11).
17. ARCH §4.4: `evictDaemonLockIfStale` deletes only when the heartbeat is older than `ttlMs` or the liveness probe says the holder is dead. It runs `startupSweep` first and never evicts a live daemon. `forceDeleteDaemonLock` is a single `DELETE ... WHERE id = 1`. Files: `store-coordinator.ts`, `daemon-queries.ts`.
18. ARCH §2 schema: all tables are `STRICT`. `events`, `messages`, `artifacts` and `blobs` are `WITHOUT ROWID`. `daemon_events` uses `AUTOINCREMENT`. Pragmas: WAL, `synchronous=NORMAL`, `busy_timeout=5000`, `foreign_keys=ON`, `temp_store=MEMORY`, 64 MB cache, 256 MB mmap, `wal_autocheckpoint=1000`, `page_size=8192` at creation. Files: `schema.sql`, `pragmas.ts`; P22 and P23 tests.
19. ARCH §2: `run_state.status` CHECK covers the nine `RunStatus` values; `change_stat < 1024` CHECK; `inbox_status` enum CHECK; `routing` < 8192. Generated columns `total_cost_usd` and `billed_tokens`. Partial indexes `idx_run_state_queue` and `idx_run_state_inbox`. `idx_run_state_checkout` is created by the v7 migration step and on every bootstrap, not by `schema.sql`. Files: `schema.sql`, `migrations.ts`.
20. SPEC §5 / ARCH §1.11 / §12: the migration counter `CURRENT_SCHEMA_VERSION` (7 per the bundle log) walks forward automatically. A store newer than the binary is refused (`checkVersion`). Each `SCHEMA_MIGRATIONS` step is `{ up, down? }`. `fragua db migrate --to <lower>` backs up first and refuses an irreversible step, a data-losing step without `--allow-data-loss`, and a live daemon. Files: `migrations.ts` (`migrateTo`, `planMigration`), `pragmas.ts`, `migrations.test.ts`, `migrate-to.test.ts`, `cli/src/commands/db*.ts`.

Blobs, GC, artifacts
34. SPEC §4 I8 / ARCH §0 / §1.2: blobs are content-addressed at `<blobsDir>/<first2>/<sha256>`. Write order is file then row, so orphans are files and never dangling rows. `blobs` has no run FK and no cascade. The `artifacts` PK is `(run_id, node_id, iteration, key)`. A same-content `putArtifact` is a no-op. A different-content rewrite throws `ArtifactCollisionError` unless `{ replace: true }`. Files: `store/src/blob*`, `artifact-queries.ts`, `store-writer.ts`; P14, P15, P26 tests.
35. ARCH §0 blob GC roots: every sha in any `run_state.routing` column, and any `outputs` row that is itself a spilled-struct ref, is a root, alongside artifact-referenced blobs. The roots are resolved inside the orphan `DELETE`. Both passes unlink under the write lock and re-check candidates inside the txn. The file-side pass skips files younger than a grace window. Every writer re-puts its file after its row commits (`enqueueRun`, the `appendFact` output spill, `putArtifact`, bundle import). Files: `store/test/blob-gc-roots.test.ts`, `blob-gc-race.test.ts`, `blob-gc-race.property.test.ts`, `routing-blobs.ts`, `routing-spill.test.ts`, `daemon/src/blob-gc.ts`.
36. ARCH §0 spill constants: `PER_VALUE_SPILL_BYTES` 1 KiB; `ROUTING_SPILL_MARGIN_BYTES` 3 KiB. The ref shape is `{ "$fragua_blob": "<sha256>", "bytes": N }`. `materializeRouting` resolves refs on read. Files: `routing-blobs.ts`, `routing-spill.test.ts`, `routing-blobs.test.ts`.
37. ARCH §2 / §2.1: `outputs` is a rebuildable index (PK `(run_id, node_id, iteration)`, `INSERT OR REPLACE`), off the `run_state` fold, written in the same transaction as `fact.node_completed`. Files: `outputs-queries.ts`, `store-outputs.ts`, `outputs-queries.test.ts`.
38. ARCH §2: `imported_runs` is the authoritative inert gate (out of dispatch, concurrency and the sweep). It is never carried in a bundle. Files: `run-state-queries.ts`, `exclude-imported.test.ts`, `store-bundle-import.ts`.

Bundles, schedules, credentials

## 3. Known-gap register (admitted by the docs; not findings)

STATUS "What fragua does not deliver today":
1. Multi-machine deployment. A single SQLite file is the coordination surface.
2. Token auth on the harness API (localhost-only, none in v0). The same-origin gate does exist. The residual exposure is "a compromised process on the same host".
3. Watchdog for stuck-but-alive daemons. Resumability covers crash-restart but not fiber deadlock. The heartbeat metric is deferred.
4. Postgres or non-SQLite backing. `IEventStore` is synchronous.
5. Workflow hot-reload for in-flight runs (`workflow_sha` pinned at enqueue).
6. Schema auto-migration across breaking bumps. An out-of-range pin gives a recoverable `engine_incompatible` pause.
7. Per-project credential isolation, project extensions, file-server, rate-limit fairness (design-stage).

SPEC §5 "Not in scope" / "Also excluded by design" (declared choices):
8. Multi-machine deployment; blob encryption.
9. Auto-migration of contract drift, with capability-gated auto-wake for the too-new arm "still deferred".
10. Schema downgrade is never automatic (operator-run `db migrate --to` only). It does not make a newer-contract run resumable on an older daemon.
11. Shell and network sandboxing of `bash`. It is arbitrary code execution on the host. The refuse-list is "coarse, trivially bypassed", and the cwd jail does not cover the bash body.
12. A live credential embedded verbatim in a binary blob is not scrubbed on export (a warning is emitted instead).
13. A manager-loop primitive, pre/post tool hooks, a blocking interviewer interface, `auto_status`, `loop_restart`. `wait_any` / `race` / `quorum` joins, cross-run fan-in and dynamic forks are excluded by design.
14. W013 unknown attributes are warnings, not errors.

SPEC §3.1.1 / §3.4:
15. Per-branch pause is "not built and won't be until there is demand". There is no partial-pause status.
16. The `signal` pause reason (external wait) is not emitted (fact-taxonomy.md §6.2, ARCH §3).
17. A direct read of an optional output leaf has no fallback syntax (W016 stays advisory).
18. The run-level outputs envelope is typed-partial by design (an unproduced output is absent, not an error).

ARCH admissions:
19. §1.6: no dispatch-identity token. A zombie daemon keeps running its node and may keep burning tokens until its next commit fails OCC ("ACCEPTED TRADE").
20. §1.7 / §13: a fiber wedged in a tight sync loop is detected only because the supervisor stops too.
21. §1.8 / §13: a provider that ignores `AbortSignal` is bounded by `Promise.race` and recorded by `handler_timeout_leaked`.
22. §1.11: the sha256 blob oracle is deferred. Intent-flood DOS is covered by the abort-loop detector, with the HTTP rate-limit noted at the web layer (no rate-limit implementation is named). Replay is not bit-identical (durability is turn-grained; the un-recorded tail re-executes).
23. §3 dirty-base accept: no partial-land resume and no post-write verify. An interrupted land is restored by hand from `refs/fragua/bases/<runId>`. The editor-write race between compare and write "is not closed".
24. §6.1: `occ-append.ts` and `wake-pending.ts` build terminal facts inline, outside the single-producer rule (unscanned).
25. §6.2: no max-branch validator bound beyond E036 (≥2) and E045. A pathologically wide fan-out fails its seed loudly (`PayloadTooLargeError`). It is a "latent validator gap". The per-branch abort-loop counter is process-local and resets on restart.
26. §0 "Bundle export/import support is pending (proposal §8, item B5)". This text conflicts with §4.5 and STATUS, which present export/import as built.
27. §2.1: `routingPatch` keys (budget overrides, retry counters, auto-resume timer) are not re-materialised by the pure fold. Their provenance stays in the log.
28. §12 deferred: retention policies (manual `fragua prune`), blob streaming over 16 MB, per-workflow concurrency caps. §8: priority starvation of lower tiers is accepted, with no `workflow_max_concurrent`. §13: SQLite write throughput is "unknown until measured".
29. §12.1: "Known gaps in coverage live as proposals" (`docs/proposals/`, not read).
30. STATUS "experimental": judge nodes, MCP tools ("connector contract and `.mcp.json` schema are not frozen"), bundle secret scrubbing ("registry, marker format, and CI exit code are not yet frozen").
31. Test-suite state at survey time: 1 skipped test (§1.1). It is the `retry_target` fail-routing retarget case, and SPEC §3.6 says that fallback no longer exists.
32. `docs/handler-contract.md`: a tool without provider dedup gets a warning label, and the operator is the only safety net ("handler-author responsibility", ARCH §1.1 item 5). Handler PR review items (checklist) are manual.

Not admitted anywhere I read (candidates for lenses to check, not asserted as findings): §1.4 doc-internal inconsistencies, the `core ↔ store` package cycle, and web's value imports from `@fragua/core` including the `./read-plane` sub-entry.
