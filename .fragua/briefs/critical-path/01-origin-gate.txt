Add a same-origin gate to the fragua HTTP server so a web page open in the operator's browser cannot drive the control plane.

Problem (verified on main). The Hono server in `packages/server/src/index.ts` mounts no CORS, `Origin`, `Host`, or content-type middleware. Hono's `c.req.json()` is `text().then(JSON.parse)` with no content-type check, so `readJson` at `packages/server/src/store/routes.ts` (the `(await c.req.json()) as T` helper) accepts a `mode: "no-cors"` text/plain POST from any origin as a simple request with no preflight. Chain: `POST /api/workflows` accepts any `{name, source}`; a two-step tool-only workflow (`type: tool`, `run: echo x`, `next: exit`) validates clean; `POST /api/runs` trusts caller-supplied `cwd`; the daemon gives a non-git `cwd` an in-place `LocalEnvironment` (`packages/daemon/src/worktree-provisioner.ts`, the `isGitRepo` branch). Result: a hostile page can run a shell command in any directory on the machine. Without a `Host` check, DNS rebinding also lets a remote origin read transcripts, blobs and skill files.

Build:
1. One Hono middleware in `packages/server/src/` applied to every route (mount it in `index.ts` before the routers), with this policy:
   - If an `Origin` header is present, it must match one of: the bound origin (scheme + host + port the server listens on, passed in from `startServer` options), `http://localhost:<port>`, `http://127.0.0.1:<port>`, `http://[::1]:<port>`, or the Vite dev origin `http://localhost:5173` / `http://127.0.0.1:5173`. Otherwise respond 403 `{ error: "cross-origin request refused", code: "forbidden_origin" }`.
   - The `Host` header must be the bound host:port or a loopback equivalent of it (localhost, 127.0.0.0/8, [::1]). Otherwise 403 `{ code: "forbidden_host" }`. When the operator binds a non-loopback `--host`, also accept that literal host. Reuse the loopback predicate that already lives in `packages/cli/src/commands/serve.ts` by moving it to a shared spot the server can import (server must not import cli).
   - For any request with a body (POST/PUT/PATCH/DELETE with content), require `content-type: application/json` (parameters allowed). Otherwise 415 `{ code: "unsupported_media_type" }`. Put the check in `readJson` too so a route that bypasses the middleware still fails closed.
   - SSE and static-asset GETs go through the same Origin/Host checks; GETs need no content-type check.
2. Update the web client only if it fails: `packages/web/src/lib/api.ts` already sends JSON; confirm it sets `content-type: application/json` on every mutating call and add it where missing.
3. Tests in `packages/server/test/`: a text/plain cross-origin POST to `/api/runs/:id/cancel` gets 403 or 415 and appends no intent; a same-origin JSON POST still works; a request with a foreign `Host` gets 403; SSE with a foreign Origin gets 403; existing route tests still pass (they may need a Host header in their fixtures; add a small helper rather than editing every call).
4. Docs: `docs/SPEC.md` §2 (the "enforced at the socket" sentence) and `STATUS.md` ("Token auth on the harness API" bullet) must state the new same-origin gate and that the residual gap is a compromised process on the same host, not a browser tab. `CHANGELOG.md` Unreleased / Fixed: one sentence.

Constraints: no new runtime dependency. Do not add token auth. Do not change the intent plane. Keep the middleware under ~80 lines. Follow AGENTS.md commit conventions if you commit, but leave the tree uncommitted for the operator to accept.
